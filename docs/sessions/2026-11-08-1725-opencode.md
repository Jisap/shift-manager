## Objetivo

Implementar la recuperación de contraseña por OTP con Resend, último hueco del MVP de autenticación.

## Hecho

- [x] **Proveedor de reset con OTP:**
  - Nuevo `convex/resendOtpPasswordReset.ts` basado en `@auth/core/providers/resend`.

## Decisiones tomadas

- El código OTP es de 8 dígitos y caduca en 24 horas, siguiendo la guía de Convex Auth.
- La solicitud de reset no distingue entre email registrado y no registrado para evitar enumeración de cuentas.
- La validación de contraseña exige 8 caracteres como mínimo, igual que el alta.
- Las credenciales de Resend viven solo en el entorno de Convex; nunca en `.env.local` ni en el cliente.
- Se mantiene `onboarding@resend.dev` como remitente de respaldo si `AUTH_EMAIL_FROM` no está definido.

## Seguimiento (17:40) — diagnóstico del error de envío con Resend

El usuario reportó el error de Convex `No se pudo enviar el código de recuperación`. Se comprobó la configuración del deployment:

- `AUTH_EMAIL_FROM` = `onboarding@resend.dev`.
- `AUTH_RESEND_KEY` presente.
- La cuenta de Resend **no tiene ningún dominio verificado** (`GET /domains` devuelve lista vacía).

Consecuencia: el remitente de pruebas `onboarding@resend.dev` solo puede entregar al **correo propietario de la cuenta de Resend**. Cualquier otro destinatario es rechazado por la API.

Cambio en `convex/resendOtpPasswordReset.ts`:

- El error de Resend ya no se oculta: se registra en los logs de Convex con remitente, destinatario, `name` y `message`.
- Si el remitente es `resend.dev`, se añade una pista explícita sobre la restricción del correo propietario y la necesidad de verificar un dominio.
- El error lanzado incluye ahora el `name` y `message` de Resend para facilitar el diagnóstico.
